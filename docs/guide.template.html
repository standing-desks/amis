Keep the base small; make evolution explicit. JSON records, declared source evidence, revision history, scope and integrity are the portable core. Embeddings, transport, encryption and signatures can become versioned profiles. Nothing unknown is silently discarded or interpreted as permission.




AMIS · Agent Memory Interface Spec
An independent contract.
A small core that can evolve.
No application owns the meaning of a record. Providers implement the same core and explicitly advertise the profiles they support. Storage, language, UI and transport remain implementation choices.




Vendor neutral on the wire
amis.bundle and amis.record. Open provider identifiers and versioned profiles. No product, database, operating system or SDK dependency.
Honest provenance
Unknown authorship stays unknown. Known source bytes may be included, withheld, erased or unavailable. The receiver sees evidence limits before publication.
Independent conformance
Validate with multiple implementations and shared vectors before 1.0. Passing core validation does not imply native publication or synchronization support.


AMIS is the selected project name for this draft. It is a proposed specification, not an adopted industry standard. No public domain, registered media type or unique acronym is claimed. Files currently use application/json and the .amis.json naming convention.




Three designs · One shared format
Choose how memories move.
The same AMIS bundle works in all three. Begin with the local library; portable packs and continuous sync can reuse its adapters and revision engine.






Recommended sequence: library → packs → optional sync. “Every harness has every memory” means all approved, in-scope records have a tracked delivery to each selected target. Exceptions remain visible; an implementation must not report universal sync while records are blocked or awaiting consolidation.




Protocol behavior
Six operations.
One accountable round trip.
Operations have transport-independent semantics. Each language or transport binding must preserve the same results and errors. Each operation returns explicit outcomes rather than an unqualified “synced.”

Conversion preserves meaning
Deterministic parsing changes structure. Semantic merging or summarization creates a separate proposal with parent records.
Scope survives publication
Unknown scope holds publication. A file’s global storage location does not make its knowledge global. Native loading scope must match the intended audience.
Repeats do not multiply memories
Stable IDs and owned receipts reconnect exports. Equal wording alone never establishes identity or a second independent source.
Changes remain reviewable
Compare base export, current AMIS revision and edited native output. Divergent changes preserve both sides and pause that delivery.


Revision, trust and withdrawal rules
A revision is immutable and has its own UUID. Accepting an edit creates a new revision with exact parent references. Concurrent edits form branches; a same-ID revision with different bytes is rejected as an integrity or identity conflict. Withdrawal creates a tombstone revision and queues correction or removal of owned projections. Already-derived memories may require follow-up in the harness.
Incoming bundles are untrusted evidence. Approval is a separate local decision bound to the record digest, current heads, scope mapping and exact output plan. Nothing in an imported bundle grants write authority. An embedded marker requires a matching local receipt. Unknown required features allow archival retention, but block synchronization.

Native evidence and implementation boundaries
Claude’s memory documentation describes repository stores, an index budget of 200 lines or 25KB, topic files loaded on demand, and context imports. The Codex context route follows its AGENTS.md discovery rules. The native Codex ad-hoc note candidate comes from inspected source at a pinned revision; it is not a stable cross-harness import API.
Read live databases only through private database/WAL snapshots. Report unsupported versions, unreadable files and size limits. Instruction files, skills, settings and transcripts remain classified as such until reviewed; discovery does not automatically turn every file into a durable memory.




Implementation roadmap
Build the converter.
Prove the round trip.
Implement the validator and immutable record store independently of adapters. Any application can provide a library, pack exchange or synchronization UI on the same contract.
01Record + bundle
Validate schema and source hashes. Persist stable identity and immutable revisions. Preserve unknown fields.
02Reviewed publication
Connect an application’s memory browser to target previews. Resolve scope, show exact diffs, create a guarded write plan.
03Round-trip conformance
Prove both directions in isolated homes. Test retries, crashes, native edits, conflicts and withdrawal.
04Continuous operation
Add bounded resumable scans, optional watchers and per-record delivery coverage. Add semantic merge proposals later.
Definition of done: the same approved record can travel through both adapters without losing identity, silently widening scope, duplicating evidence or hiding a failed delivery. A supported route must demonstrate fresh-session loading at its advertised level. Unsupported routes stay blocked.
